\chapter{Quality criteria}
\textbf{Quality criteria} describe the secondary requirements.
Per their nature, they are \textit{nonfunctional}, i.e.~don't define \textit{what}, but rather \textit{how} something is done.
Quality criteria are not visible to the immediate user, but deal with topics like legal regulations, data privacy, security or safety.

\qualityReq{10}{Database injection must not be possible.}
\qualityReq{20}{No personally identifiable information (\textit{\hyperref[abr:PII]{PII}}) must be shared with external services.}
\qualityReq{30}{The code generation must not take longer than 30 seconds. In case it takes longer, that generation is counted as failed.}
\qualityReq{40}{All user passwords should only be persisted using a secure, one-way encryption algorithm.}
\qualityReq{50}{The system should limit concurrent users to prevent overloading the server.}
\qualityReq{60}{All server-side logging should be performed using a logging framework to ensure structured logs, maintainability and effective debugging.}
\qualityReq{70}{The front-end should handle all operations without runtime errors.} 
\qualityReq{80}{The front-end should not produce any errors in the browser console during normal operation.}
\qualityReq{90}{All communication between front-end and back-end should be encrypted.}
\qualityReq{100}{The system could be deployable using containerization.}
\qualityReq{110}{The system could allow integration with \hyperref[abr:CI/CD]{CI/CD} pipelines to automatically test or deploy generated code.}
\qualityReq{120}{The interface of the system should be responsive on the display sizes \textit{Mobile Phone}, \textit{Tablet} and \textit{Desktop}. It should also be accessible according to the \textit{Material Accessibility Guidelines} \footnote{https://m3.material.io/foundations/overview/principles}.}
\qualityReq{130}{The \textit{\hyperref[abr:LLM]{LLM}} and \textit{Database} should be stored on a secure server and can only be accessed by authorized actors.}
